B. True-device IME / toolbar regression fix — PASS (logic/static)
Observed on Beta V1.0 true device:
- Read -> Edit successfully opened the Honor keyboard, but the bottom format bar could remain at physical screen bottom behind the IME.

Fix implemented:
- Existing WindowInsets listener behavior is preserved but dispatch is centralized in MainActivity.dispatchImeInsetsToWeb().
- New read-only JS bridge requestNoteImeInsets() queries ViewCompat.getRootWindowInsets(webView) on demand.
- Entering Edit Mode probes native IME geometry at 0 / 70 / 160 / 300 / 480 ms across the keyboard opening animation.
- Positive native WindowInsets remains authoritative.
- When the last native value is stale zero, a genuine >=80 CSS px visualViewport shrink may temporarily drive the same --note-ime-space layout until a positive native value arrives.
- Probe timers are cancelled on Read Mode, suspend and close.
- No fixed/sticky toolbar rewrite was introduced; the existing V1.22.3 flex + single Scroll Owner layout is preserved.

Exact-function Node regression:
- physical native inset 600 px at devicePixelRatio=3 -> --note-ime-space=200px: PASS.
- note-ime-visible class toggles on positive inset: PASS.
- stale native 0 + visual 190 -> visual fallback 190: PASS.
- positive native 240 overrides visual fallback: PASS.
