# 数据迁移与备份（候选版）

## 必须保留旧数据

新旧包名不同，旧 1.40.6 没有完整导出接口。当前提供显式桥接导出/本地恢复，
“首次打开无感自动迁移”未实现。不要卸载旧 To-Do，也不要清除数据解决签名冲突。

1. 核对手机上旧 To-Do 与桥接 APK 签名一致；若提示卸载，立即停止。
2. 覆盖更新到 To-Do-1.40.7-Migration-debug.apk（versionCode 1407）。
3. 旧应用顶部“迁移备份”导出 ZIP；妥善保管，可能包含 AI 密钥等私密数据。
4. 尚无内容的 Nexa：Space → 数据迁移与备份 → 从完整备份恢复。
5. 验证数量、正文、图片、文件、Daily 历史和提醒；始终保留原应用和备份。
6. 两个应用可能重复提醒，验收后由用户决定在哪边保留提醒；不擅自删除旧记录。

本机原 1.40.6 APK 与桥接包签名 SHA256 相同：
57ad983bf70aec4d668d2a0e6f7ea850afd0f0724f021f926372bf27b28eeddb。
这不证明手机上安装的那份 APK 一定具有此签名。

## 范围与保护

归档包含所有 localStorage 字符串、note_images、note_files 和类型化原生设置。
包括任务、清单、笔记、主题、Daily、回收站、搜索历史、Space、工具栏与 AI 设置。
旧应用尚未完成的分享 Intent/附件导入队列只归档，不跨包重放。
清单逐项记录大小和 SHA256。恢复校验路径、重复项、清单完整性和哈希，
拒绝覆盖已有记录、标签或附件，不做未经验证的跨库合并。

安全上限：解压总量 1 GiB、JSON 单项 32 MiB、20,000 项；超限拒绝，不丢弃附件。
需要足够临时空间。备份没有加密，只保存在用户选择的位置，不上传网络。

先暂存验证、再在页面初始化前恢复；原生提交失败回滚，重启恢复中断的提交。
原生测试覆盖附件与设置往返、拒绝覆盖、路径穿越、提交失败和中断恢复。
物理手机 SAF 全流程、真实大库和极端磁盘故障仍待验收。

参考：[Android 应用安全](https://developer.android.com/privacy-and-security/security-tips)。
